# Восстановление бригад из зашифрованного снапшота

## Требуемые конфигурационные данные в датацентре

* В датацентре есть публичный RSA ключ исхлдного датацентра, в котором делаем снапшот (`dc-rsa-pub_key`)
* В датацентре есть публичные ключи сервисов-исполнителей, которые могут расшифровать бэкап (`auth-rsa-pub_keys`)
* Для восстановления так же используется секретный RSA ключ датацентра, для которого бэкапим (`dc-rsa-priv_key`)
* Для восстановления в датацентре у сервиса-исполнителя есть приватный RSA ключ для расшифровки бригад `auth-rsa-pub_key`

## Требуемые конфигурационные данные в министерстве

*  Для восстановления в министерстве у сервиса-исполнителя есть приватный RSA ключ для расшифровки бригад `auth-rsa-pub_key`

## Общий принцип

* Создаётся специальный набор снапшотов (мгновенных копий) бригад или берётся готовый в датацентре, их которого нужна миграция или восстановление
  * Специальный набор снапшотов используется в том числе для того, чтобы установить режим обслуживания в бригадах
* Создаётся именованное резервирование слотов в целевом датацентре и собирается метаинформация (контрольные ноды, внешние IP, `router_key` каждой "пары нод")
* Набор снапшотов перешифровывается в датацентре для конкретного сервиса-исполнителя 
* C помощью перешифрованного для сервса-исполнителя набора снапшотов и конфигурации резервирования в целевом датацентре (даже если это тот же) сервисом-исполнителем создаётся подготовленный для восстановления группированный набор снапшотов, перешифрованный для конечных контрольных нод
* Группами, сформированными по контрольным нодам, создаются бригады в целевом датацентре
  * Сервисом-исполнителем является специальный сервис датацентра, если переезд в рамках одного датацентра
  * Сервисом-исполнителем является специальный сервис министерства, если целевой и исходный датацентры различаются
* После удачной технической миграции, происходит процесс переноса доменов
* После заданного периода, бригады в исходном датацентре удаляются. Удаление производится с использованием данного набора снапшотов

## Резервирование

* Для включения контрольных нод (статус `is_active=true`) используется специальная утилита включения контрольных нод `/opt/vg-dc-admin/config_pair.sh`
* Утилита умеет включать
  * Все контрольные ноды
  * Контрольные ноды с фильтром по подсетям сервисной сети, в которой есть датацентр и контрольная нода, в том числе и списком
* Утилита включения контрольных нод  также записывает публичный `router_key` “пары нод” и фингерпринт SSH-ключа хоста каждой контрольной ноды в базу
  * Опционально утилита может обогатить базу этими данными ничего не меняя в смысле активности
  * При повторном включении каждой контрольной ноды утилита обновляет данные, сравнивая их с записанными и выдавая предупреждения
  * В дальнейшем можно собирать фингерпринт SSL-ключа роутера ключниц вместо SSH-ключа хосте для каждой контрольной ноды
* Для резервирования на целевом датацентре запускается утилита резервирования слотов `/opt/vg-dc-snaps/create_reservation.sh`
* Утилита резервирования слотов учитывает:
  * Имя резервирования
  * Количество требуемых слотов
  * Фильтр внешних IP-адресов (опционально)
  * Фильтр IP-адресов контрольных нод (опционально)
* Утилита резервирования имеет специальный режим зеркала, когда IP резервируются 1:1 в исходной и целевой подсетях (обычно это одна и та же подстеть)
* Утилита резервирования слотов умеет:
  * Создать резервирование
  * Посмотреть резервирование
  * Удалить резервирование
  * Создать конфигурацию резервирования
* Слоты, помеченные как зарезервированные, не участвуют в создании и удалении бригад общим способом
* Утилита резервирования создаёт конфигурацию для миграции, группируя зарезервированные слоты по контрольным нодам, записывает `router_key` каждой “пары” в группу

## Перешифровка набора снапшотов бригад для сервиса-исполнителя

* С помощью приватного RSA-ключа датацентра `dc-rsa-priv_key` расшифровывается psk  снапшотов и шифруется заново ключом конкретного сервиса-исполнителя утилитой `/opt/vg-dc-snaps/snap_prepare`
  * TODO: Для расшифровки `psk` используется специальный ключ.
    * Во время создания набора снапшотов он разделяется между доверенными лицами, `тег + время начала снапшота + часть ключа` шифруется публичным RSA-ключом доверенного лица `turstee-pub_key`
    * Перед расшифровкой требуется получить столько расшифрованных частей ключа, сколько требуется для консенсуса
    * Для простоты в начале консенсус равен 2, а один из `turstee-pub_key` это ключ датацентра
    * Соответственно есть специальная утилита, которая создаёт запросы для расшифровки ключа `psk`, а утилита перешифровки принимает эти части ключей как аргумент перешифровывает `psk` заданным паролем (чтобы не было никаких ключей)
* С помощью приватного RSA-ключа датацентра `dc-rsa-priv_key` расшифровывается `locker` снапшота каждой бригады и шифруется заново ключом конкретного исполнителя
* Набор снапшотов с новыми шифрованными `psk` и `locker`, а также фингерпринтом публичного ключа сервиса-исполнителя записывается

## Создание подготовленного набора сгруппированных снапшотов для восстановления

* Место перешифровывания 
  * Для восстановления сервисом-исполнителем является специальный сервис министерства
* Для создания преподготовленного набора снапшотов требуется секретный мастер `shuffler` ключ исходного датацентра и публичный мастер `shuffler` ключ целевого датацентра
  * То ли они временно размещаются, защищенные паролем
  * То ли они передаются на вход утилиты создания преподготовленного набора снапшотов
* На вход скрипта подготовки набора снапшотов `/opt/vg-head-vpnapi/recodesnaps` для восстановления подаётся
  * Перешифрованный для сервиса-исполнителя набор снапшотов бригад
  * Конфигурация резервирования для миграции
  * секретный мастер `shuffler` ключ исходного датацентра и публичный мастер `shuffler` ключ целевого датацентра
* Для каждой группы, соответствующей одной контрольной ноде, из конфигурации резервирования создаётся соответствующая группа в подготовленном наборе снапшотов
* Каждая группа заполняется из перешифрованного для сервиса-исполнителя набора снапшотов побригадно
* Для каждой группы создаётся спискок бригад и соответствующих им доменов
* Для каждой бригады
  * Расшифровываются все зашифрованные публичным мастер ключом `shuffler` данные с помощью секретного мастер `shuffler` ключа исходного датацентра и зашифровывается вновь с помощью мастер `shuffler` ключа целевого датацентра, а также публичного  ключа `router_key` целевой контрольной ноды, в которую будет размещена бригада и который есть в конфигурации резервирования
  * Прописывается новый IP
  * Обнуляется вся статистика использования 
    * Счетчики трафика
    * Количество ограниченных пользователей
    * Количество активных пользователей
    * Последние посещения
    * Последние посещённые блоки подсетей
* Полученный подготовленный для восстановления набор снапшотов бригад записывается

## Восстановление бригад из подготовленного для восстановления набора снапшотов группы (в датацентре)

* Бригады восстанавливаются утилитой восстановления в датацентре `/opt/vg-dc-snaps/restoresnaps` из подготовленного для восстановления набора снапшотов
* Утилита восстановления может восстанавливать как весь подготовленный для восстановления набор снапшотов, так и только выбранную группу, соответствующую контрольной ноде
* Утилита восстановления принимает на вход
  * Подготовленный для восстановления набор снапшотов группы (гурппа бригад на одной контрольнуй ноде) для данного резервирования
* Утилита восстановления осуществляет
  * Для каждой бригад создаёт новую бригаду в базе данных, связывает с заявленным слотом из резервирования
    * НЕ привязывает поддомен бригады к новому внешнему IP, создаёт бригады без доменов. Но в конфиге домен есть
    * НE перетаскивает на себя поддомен из API поддоменов
    * НE проверяет делегирование поддоменов
    * НE проверяет делегирование поддоменов ключниц
    * Создаёт бригаду без признака “главная”
  * Делает вызов специального API на контрольной ноде и передаёт набор подготовленных для восстановления снапшотов группы

## Восстановление бригад из подготовленного для восстановления набора снапшотов группы (на контрольной ноде)

* Для каждой бригады в подготовленном для восстановления набора снапшотов группы скрипт восстановления `/opt/vgkeydesk-restore/restorebrigades.sh`: 
  * Создаёт бригаду без создания базы бригады (подготавливает), создаёт вспомогательные каталоги
  * Кладёт готовую конфигурацию бригады из снапшота, установив нужные права (встроить в `create_brigade.sh`?)
  * Делает replay через sudo (встроить в `create_brigade.sh`?)
  * Запускает нужные systemd

## Переключение бригад и миграция поддоменов при восстановлении набора снапшотов

* После создания копий бригад требуется переключить их, т.е.
  * Указать министерству, что процесс перевыпуска конфига теперь происходит в бригаде в другом датацентре
  * Указать датацентру, что процесс перевыпуска конфига происходит теперь в бригаде в другом инстансе
  * Внести новую запись IP-адреса поддомену бригады
* В случае миграции в одном датацентре переключение осуществляет утилита локального переключения бригад `/opt/vg-dc-snaps/switch_local_migr.sh` в датацентре
  * на вход поступает:
    * команда (в данном случае `switch`)
    * снапшот бригад или подготовленный снапшот бригад
    * имя резервирования для проверки
    * фильтр по IP подсетям контрольных нод (опционально)
    * фильтр по IP внешним подсетям  (опционально)
  * побригадно проверяет, что новая бригада находится в заданном резервировании
  * побригадно переключает
    * в предыдущем экземпляре бригады удаляет домен
    * в предыдущем экземпляре бригады устанавливает флаг второстепенной
    * удаляет из базы связь домена и предыдущего IP-адреса
    * добавляет в базу связь домена и нового IP-адреса
    * в новом экземпляре бригады прописывает домен
    * в новом экземпляре бригады устанавливает флаг главной
  * после переключения необходимо сделать синхронизацию доменов
* В случае миграции между датацентрами следует
  * Принять новые бригады в новом датацентре утилитой принятия бригад `/opt/vg-dc-snaps/accept_remote_migr.sh` в датацентре
    * На вход утилита принимает
      * имя резервирования для проверки
      * план восстановления бригад
      * фильтр по IP подсетям контрольных нод (опционально)
      * фильтр по IP внешним подсетям  (опционально)
    * побригадно проверяет, что новая бригада находится в заданном резервировании
    * побригадно переключает
      * добавляет в базу связь домена и нового IP-адреса
      * в новом экземпляре бригады прописывает домен
      * в новом экземпляре бригады устанавливает флаг главной
  * Переключить основной датацентр бригад в министерстве утилитой переключения бригад `/opt/vg-head-vpnapi/switch_remote_migr.sh` в министерстве
    * На вход утилита принимает
      * команду (в данном случае `switch`)
      * снапшот бригад или подготовленный снапшот бригад
      * ID целевого датацентра
      * побригадно
    * устанавливает флаг основного датацентра для бригады целевому датацентру
    * устанавливает флаг второстепенного датацентра для бригады исходному датацентру
  * Освободить бригады в исходном датацентре утилитой освобождения бригад `/opt/vg-dc-snaps/release_remote_migr.sh` в датацентре
    * На вход утилита принимает
      * снапшот бригад или подготовленный снапшот бригад
      * фильтр по IP подсетям контрольных нод (опционально)
      * фильтр по IP внешним подсетям  (опционально)
    * побригадно
      * удаляет из базы связь домена и предыдущего IP-адреса
      * в предыдущем экземпляре бригады удаляет домен
    * составляет список освободившихся доменов
    * после освобождения необходимо сделать синхронизацию доменов в этом датацентре
  * Передать поддомены в резервирование в исходном датацентре утилитой резервирования поддоменов `/opt/vg-dc-snaps/subdomain_reservation.sh`
    * на вход утилиты поступает
      * команда (в данном случае `create`)
      * ID целевого датацентра
      * ID целевого резервирования
      * файл освободившихся поддоменов
    * отдаёт поддомены в резервирования системе обслуживания поддоменов
  * Принять поддомены в резервирование в целевом датацентре тилитой резервирования поддоменов `/opt/vg-dc-snaps/subdomain_reservation.sh`
    * на вход утилиты поступает
      * команда (в данном случае `release`)
      * ID целевого резервирования
      * файл освободившихся поддоменов
    * принимает поддомены в резервирование в целевом датацентре

## Миграция поддоменов ключниц при восстановлении набора снапшотов

* Ничего специального не требуется т.к. IP ключниц остаются теми же

## Очистка после миграции

* Утилитой локального переключения бригад `/opt/vg-dc-snaps/switch_local_migr.sh` в целевом датацентре для локальной миграции и в исходном датацентре для миграции между датацентрами удалить втопростепенные бригады
  * на вход поступает:
    * команда (в данном случае `delete`)
    * снапшот бригад или подготовленный снапшот бригад
    * имя резервирования для проверки **!!!! надо это убрать**
    * фильтр по IP подсетям контрольных нод (опционально)
    * фильтр по IP внешним подсетям  (опционально)
  * побригадно проверяет, что новая бригада находится в заданном резервировании
  * побригадно удаляет второстепенные бригады и их статистику
* При миграции между датацентрами
  * Утилитой переключения бригад `/opt/vg-head-vpnapi/switch_remote_migr.sh` в министерстве удалить связь со второстепенным датацентром
    * На вход утилита принимает
      * команду (в данном случае `delete`)
      * снапшот бригад или подготовленный снапшот бригад
      * ID исходного датацентра
    * побригадно удаляет связь с исходным датацентром
* Утилитой создания реpервирования  в целевом датацентре `/opt/vg-dc-snaps/create_reservation.sh` удалить соответствующее резервирование с флагом `-f`
