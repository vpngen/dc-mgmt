# Бэкап бригад с шифрованием

## Требуемые конфигурационные данные на контрольной ноде

* На контрольной ноде есть публичный RSA ключ исходного датацентра, в котором бэкапим  (в формате списка ключей  `dc-rsa-pub_keys`)
* На контрольной ноде есть публичные ключи сервисов-исполнителей, которые могут расшифровать бэкап (`auth-rsa-pub_keys`)
* Эти ключи распространяются в пакете `vgkeydesk-snap-auth`

## Требуемые конфигурационные данные в датацентре

* В датацентре есть публичный RSA ключ исходного датацентра, в котором бэкапим  (в формате списка ключей `dc-rsa-pub_keys`)
* В датацентре есть публичные ключи сервисов-исполнителей, которые могут расшифровать бэкап (`auth-rsa-pub_keys`)

## Cоздание набора снапшотов бригад на контрольной ноде 

* На контрольной ноде для забора набора снапшотов бригад отдельный SSH-вход (пакет `vgkeydesk-snap-access`).
* Утилита создания набора снапшотов бригад (`/opt/vgkeydesk-snap/fetchsnaps.sh`, пакет `vgkeydesk-snap`):
  * принимает на вход:
    * общий для всех бригад секрет для шифрования (`psk`), уникальный для этого процесса создания набора снапшотов
    * тэг набора снапшотов и общее время начала процесса создания набора снапшотов
    * время конца режима обслуживания (если требуется)
    * фингерпринт публичного ключа датацентра в котором бэкапим (обязывает запрашивающего знать этот ключ)
    * список бригад, которые нужно заснапшотить
  * обходит бригады из списка (не обходит те, что не просили) и запускает через sudo скрипт создания снапшота конкретной бригады 
  * объединяет результат в набор снапшотов
  * добавляет значения количества снапшотов и количества ошибок взятия снапшота
  * выдаёт результат
* Утилита создания снапшота одной бригады (`/opt/vgkeydesk-snap/snapshot`, пакет `vgkeydesk-snap`) 
  * принимает на вход:
    * общий для всех бригад секрет для шифрования (`psk`), уникальный для этого процесса создания набора снапшотов
    * тэг набора снапшотов и общее время начала процесса создания набора снапшотов
    * время конца режима обслуживания (если требуется)
    * фингерпринт публичного ключа датацентра в котором бэкапим (обязывает запрашивающего знать этот ключ)
  * создаёт секреты:
    * из списка ключей `dc-rsa-pub_keys` выбирается один `dc-rsa-pub_key`, соответствующий переданному фингерпринту публичного RSA ключа датацентра
    * `locker` - секрет затем шифруется выбранных публичным ключом датацентра `dc-rsa-pub_key`, служит для закрепления итогового снапшота за датацентром (и потом перешифровывается в датацентре для конкретного сервиса-исполнителя)
    * `secret` или `main secret` - секрет затем шифруется публичными ключами каждого сервисов-исполнителей (`auth-rsa-pub_keys`); служит для ограничения возможности дешифрования только ограниченным кругом сервисов-исполнителей на уровне контрольной ноды
  * создаёт итоговый ключ шифрования `<тэг> + <id бригады> + <unix time общего времени начала процесса создания снапшотов> + <unix time текущего времени> + psk + locker + secret` (требует применения метаинформации)
  * сжимает `brigade.json` алгоритмом gzip и шифрует полученные сжатые данные аналогично `openssl enc -aes-256-cbc -pass zzz ...`
  * включает режим обслуживания бригады, если соответствующие параметры были переданы
